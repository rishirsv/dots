# Naming Features And Controls

Start with the audience and the benefit they seek. Describe what they should
understand, feel, and do when they encounter the feature. Generate candidate
names from recurring user needs or product themes. Avoid internal implementation
terms when users would not understand them.

Compare candidates against the app's existing vocabulary, the outcome each name
promises, and the languages and contexts where it must work. Try them in real
navigation, instructions, and spoken sentences. Prefer a familiar neutral term
when ambiguity would undermine trust. Use action wording for an operation.

Expressive or invented names can work when their meaning is discoverable in
context. Explain any loss of clarity. An unusual name is not a benefit by
itself. Keep one term for the same concept across the experience.

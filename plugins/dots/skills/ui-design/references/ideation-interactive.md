# Exercise Content And Tune Interactions

Keep named preview states for realistic, empty, crowded, and unusually long
content. Reuse editable fixtures so a content change can be compared across
variants. Use generated fixtures to find design weaknesses. Use feedback from
people who use the product to assess their needs and experience. For stress
testing an existing component against reachable production cases, read
[component stress](component-stress.md).

When several parameters interact, build a temporary tuning panel beside the
preview. Name the animation phases and expose only the values under comparison.
Preserve the selected values in the implementation. Unless the user requested
the tuning panel as a product feature, remove it from product UI.

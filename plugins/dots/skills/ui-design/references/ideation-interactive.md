# Exercise Content And Tune Interactions

Keep named preview states for realistic, empty, crowded, and unusually long
content. Reuse editable fixtures so a content change can be compared across
variants. Generated fixtures expose design weaknesses; they do not substitute
for feedback from people who use the product. For stress testing an existing
component against reachable production cases, read [component stress](component-stress.md).

When several parameters interact, build a temporary tuning panel beside the
preview. Name the animation phases and expose only the values under comparison.
Preserve the selected values in the implementation and remove the tuning panel
from product UI unless it is itself requested.
